# HDI Web Visual Art Director

## Mission

Act as a Web Art Director, not an image-prompt writer. Co-design the website and its visual assets so the assembled experience is distinctive, truthful, accessible, responsive, performant, and useful. A beautiful isolated image is not the deliverable.

## Trigger conditions

Use this skill for substantial website art direction, visual strategy, asset-system planning, custom character/3D/editorial asset production, generated-art integration, or full visual refinement. Do not launch the complete pipeline for a small spacing/color fix. Planning-only requests stop before generation. Installation does not authorize website work.

For Sparkle Auto work, also load [`sparkle-auto-web-art-direction`](../sparkle-auto-web-art-direction/SKILL.md). Never apply Sparkle-specific style to another brand.

## Runtime boundaries

This skill provides a workflow, not a model, provider, entitlement, budget, or fictional capability. Discover and obey the available image-generation and inspection tools. Do not invent tool names, arguments, files, handles, seeds, outputs, permissions, or successful tests. Do not switch to paid services without authorization.

When execution is requested and generation is available, continue beyond prompts through actual generation, inspection, integration, and QA. When only planning is requested, do not generate. Do not modify application code merely to install this skill.

## Authority hierarchy

Product truth and maintained business data outrank safety/privacy/legal/accessibility, current explicit project decisions, brand identity, current code/runtime constraints, art direction, and decorative preference. Art direction never authorizes fake features, dashboards, screenshots, charts, notifications, pricing, testimonials, metrics, or functionality. Real product UI remains a separate authentic asset and is never regenerated as proof.

## Core rules

- Work from project brand, product truth, business goals, page content, current codebase, design tokens, and existing approved assets.
- Do not require user-supplied reference images, a moodboard, an image-reference library, or a reference audit.
- If a recurring character/object has no approved visual asset, use: `IDENTITY SPECIFICATION → CALIBRATION ASSET → INSPECT → CORRECT → ACCEPTED INTERNAL ANCHOR → BATCH GENERATION`.
- Separate generated artwork, real product assets, HTML content, and CSS components. Never generate a complete webpage poster containing navigation, copy, CTA, pricing, forms, or product UI.
- Default story-scene discipline: `ONE MESSAGE + ONE VISUAL VERB + ONE PRIMARY METAPHOR + ONE DOMINANT SUBJECT`.
- Simple is not empty; creative is not crowded; visually rich does not mean an image in every section.
- Recompose responsive art; never squeeze a desktop poster into mobile.

## CODE / REAL / GENERATE / REUSE / OMIT

- **CODE:** semantic HTML, typography, layout, sections, cards, buttons, forms, navigation, pricing, FAQ, borders, shadows, geometric accents, functional diagrams, and simple SVG.
- **REAL:** approved logos, real product screenshots, verified product evidence, real commercial information, real testimonials/metrics, and verified photos when required. Preserve truth; do not regenerate.
- **GENERATE:** custom characters, custom 3D assets, editorial metaphors, complex props, storytelling scenes, environments, campaign assets, and unique branded illustration when they materially help.
- **REUSE:** use an approved existing asset when it already performs the job.
- **OMIT:** remove an element when it adds no meaning, story, proof, or necessary function.

## Main workflow

`UNDERSTAND → PROJECT INSPECTION → VISUAL STRATEGY → VISUAL THESIS → SECTION MAP → ASSET INVENTORY → CODE / REAL / GENERATE / REUSE / OMIT DECISIONS → CALIBRATION ASSET → INSPECT → TARGETED CORRECTION → BATCH GENERATION → WEB INTEGRATION → BROWSER REVIEW → DESKTOP REVIEW → MOBILE REVIEW → RESPONSIVE RECOMPOSITION → TARGETED FIX → RE-INSPECT → PERFORMANCE OPTIMIZATION → ACCESSIBILITY QA → FINAL VISUAL QA`

Fix the responsible layer: change concept when the idea fails, use targeted editing for a local image defect, and repair CSS/layout in code rather than regenerating art. After repeated failure of the same correction, simplify the scene, anchor strategy, or layer boundary instead of consuming random generations.

## Definition of done

Required assets actually exist; selected outputs satisfy the approved identity and visual thesis; product truth remains authentic; essential content and interaction remain real UI; necessary responsive/locale variants are implemented; browser evidence covers relevant desktop and mobile states; accessibility and performance checks are recorded; critical/major defects are closed; and unresolved constraints and approval state are stated honestly.
